## Root cause

HYPOTHESIS CONFIRMED: Import-time config path freezing defeated monkeypatch.chdir()

The `blockchain` fixture in tests/conftest.py did NOT pass an explicit storage_backend:

  @pytest.fixture
  def blockchain(isolated_data_dir, wallets):
      from blockchain import Blockchain

      return Blockchain(
          project_owner_wallet=wallets["owner"],
          Contributor_one=wallets["contributor_one"],
          Contributor_two=wallets["contributor_two"],
          # storage_backend parameter OMITTED - defaults to None
      )

When storage_backend=None, Blockchain.__init__ (blockchain.py:218) executes:

  self.storage = storage_backend or create_storage_backend()

This calls create_storage_backend() with no arguments, which defaults to:

  JSONStorageBackend(blockchain_file=config.BLOCKCHAIN_FILE, ...)

config.BLOCKCHAIN_FILE is computed at module import time (config.py:637):

  NODE_DATA_DIR = _clean_path(os.getenv("NODE_DATA_DIR", os.getenv("DATA_DIR", ".")))
  DATA_DIR = NODE_DATA_DIR  # = "."
  _DATA_PATHS = build_data_paths(DATA_DIR)
  BLOCKCHAIN_FILE = _DATA_PATHS["blockchain_file"]  # = ".\blockchain.json"

FROZEN at import time to relative path ".\blockchain.json"

Even though isolated_data_dir calls monkeypatch.chdir(test_data_dir), the storage
backend was created with the pre-computed relative path that still resolved to the
repository root in practice. The problem: each test fixture reused the same frozen
path defaults, resulting in all tests sharing one blockchain.json.

The fix: explicit absolute path injection at fixture time bypasses the frozen
config constants entirely.

## Fix

File Changed: tests/conftest.py

Lines 37-45 OLD:
  @pytest.fixture
  def blockchain(isolated_data_dir, wallets):
      from blockchain import Blockchain

      return Blockchain(
          project_owner_wallet=wallets["owner"],
          Contributor_one=wallets["contributor_one"],
          Contributor_two=wallets["contributor_two"],
      )

Lines 37-63 NEW:
  @pytest.fixture
  def blockchain(isolated_data_dir, wallets):
      from blockchain import Blockchain
      from storage import create_storage_backend

      # Create storage backend with explicit test directory paths (not frozen config paths).
      # This ensures each test fixture instance loads/saves to its own isolated directory,
      # never touching repository-root blockchain.json, wallets, or feedback/audit state.
      storage_backend = create_storage_backend(
          blockchain_file=str(isolated_data_dir / "blockchain.json"),
          peers_file=str(isolated_data_dir / "peers.json"),
          sqlite_db_path=str(isolated_data_dir / "zoidbergchain.db"),
      )

      # Diagnostic: verify storage is not pointing to repository root.
      assert str(isolated_data_dir) in storage_backend.blockchain_file, (
          f"Storage backend blockchain_file must be inside test directory. "
          f"Expected substring: {isolated_data_dir}, "
          f"Got: {storage_backend.blockchain_file}"
      )

      return Blockchain(
          project_owner_wallet=wallets["owner"],
          Contributor_one=wallets["contributor_one"],
          Contributor_two=wallets["contributor_two"],
          storage_backend=storage_backend,
      )

Key Changes:
1. Import create_storage_backend and pass explicit absolute paths
2. Each parameter (blockchain_file, peers_file, sqlite_db_path) explicitly set
3. Diagnostic assertion verifies isolation at fixture setup time
4. No reliance on frozen config constants

This guarantees:
- Each test instance gets unique temp directory
- Absolute paths prevent ambiguity
- Repository-root blockchain.json never touched
- Complete test isolation

Rejecting Condition (api.py:_enforce_submission_eligibility at lines 2908-2929):

  def _enforce_submission_eligibility(wallet_address: str):
      decision = access_decision_for_wallet(blockchain, wallet_address, feature="submissions")
      submission_status = _submission_eligibility_for_wallet(
          wallet_address,
          wallet_session_authenticated=True,
          access_decision=decision,
      )
      if submission_status["can_submit"]:
          return decision, submission_status
      raise HTTPException(
          status_code=403,
          detail={
              "error": "submission_not_eligible",
              "reason": submission_status["blocked_reason"],
              ...
          },
      )

Root Cause:
1. Test creates new Ethereum wallet: creator = _create_metamask_account()
2. Wallet authenticates successfully via /auth/wallet/verify
3. Wallet attempts POST /auth/wallet/submission-challenge
4. _enforce_submission_eligibility() calls access_decision_for_wallet()
5. This function checks blockchain's persisted state:
   - blockchain.access_accounts (STALE from repo-root blockchain.json)
   - blockchain.wallet_bindings (STALE)
   - blockchain.allowlist_entries (STALE)
6. New wallet address NOT in any of these stale lists
7. blocked_reason = "wallet_not_in_allowlist_or_approved_access"
8. Returns 403 Forbidden

Why Now Fixed:
- Each test now gets fresh blockchain with only genesis state
- No stale access control data loaded from repository-root
- New wallet passes eligibility checks (clean state)
- No 403 errors
